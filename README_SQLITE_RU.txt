HSE CLUBS NN — SQLITE, TELEGRAM-ПРОФИЛИ И АДМИНИСТРАТИВНЫЕ ДАННЫЕ

ИСТОЧНИК ДАННЫХ
- Категории: categories.
- Клубы и карточки: clubs, club_photos.
- События: events.
- Пользователи Telegram: users. В таблице хранятся telegram_id (стабильный ключ учётной записи), username, first_name, last_name, photo_url, language_code, is_premium, chat_id, роль и даты активности.
- Подписки пользователей: subscriptions.
- Заявки пользователей: requests; файлы заявок: request_files.
- История статусов и обратной связи по заявкам: request_status_history.
- Уведомления в приложении и результат попытки отправки в Telegram: app_notifications.
- Активность пользователей для аналитики: user_activity.
- Администраторы и их роли: admin_accounts. Для совместимости роль дублируется в users.role; доступ предоставляется только при согласованном действующем аккаунте администратора.
- Попытки ввода кода администратора: admin_access_attempts. Код и введённые пароли в эту таблицу не записываются.
- Журнал административных действий: admin_audit_log.
- Рассылки: broadcasts; получатели и результаты отправки: broadcast_recipients.
- Внешние ссылки приложения: site_links.
- Публичные контакты администрации: admin_contacts.
- Общие настройки приложения: app_settings.

АВТОРИЗАЦИЯ TELEGRAM
Mini App не просит пользователя создавать отдельный логин и пароль. При открытии внутри Telegram приложение получает initData. Сервер проверяет подпись данных через TELEGRAM_BOT_TOKEN и сохраняет профиль пользователя. Уникальный ключ — Telegram ID; username (ник с @) используется как отображаемое имя/контакт, потому что username может отсутствовать или меняться. ФИО и username берутся из Telegram, а не из произвольного ввода на клиенте.
В production запросы без корректного initData отклоняются. При проверке дополнительно учитывается срок действия auth_date.

КОД АДМИНИСТРАТОРА
Секретный код не зашит в server.js, HTML, CSS, базе данных или репозитории. Он читается только из переменной окружения ADMIN_ACCESS_CODE. После корректного ввода в базе сохраняется назначенная роль администратора, а не сам пароль. Неудачные попытки ограничены: после пяти ошибок за 15 минут ввод временно блокируется для этого Telegram-пользователя.

ЛОКАЛЬНЫЙ ЗАПУСК НА MAC
1. Установите Node.js 22.13.0 или новее (используется встроенный node:sqlite).
2. Откройте эту папку в VS Code.
3. Выполните npm install.
4. Для локального тестирования задайте ADMIN_ACCESS_CODE в переменных окружения или в локальном файле .env, затем выполните npm start.
5. Для реального Telegram-входа задайте TELEGRAM_BOT_TOKEN. Перед публичным production-запуском также задайте NODE_ENV=production.
6. Откройте http://localhost:3000 только для локальной проверки; реальный вход Telegram работает при открытии Mini App из бота.

СЕКРЕТЫ
- ADMIN_ACCESS_CODE — секретный код для назначения роли администратора.
- TELEGRAM_BOT_TOKEN — токен бота, необходимый для проверки Telegram initData и отправки сообщений.
- SQLITE_DB_PATH — необязательный полный путь к файлу БД.
Не помещайте реальные значения секретов в server.js, HTML, CSS, README или GitHub. Локальный файл .env исключён через .gitignore; на хостинге задавайте значения в разделе Environment / Variables. Шаблон .env.example не содержит секретов.

ПУТЬ К SQLITE
В локальном запуске используется hse_nn_clubs.db в корне проекта. На хостинге задайте SQLITE_DB_PATH на файл внутри постоянного диска, например /data/hse_nn_clubs.db. Если файл по этому пути отсутствует, сервер один раз копирует в него исходную базу; существующая БД не перезаписывается.

КОНТАКТЫ И ССЫЛКИ
Публичные ссылки и контакты больше не размещаются непосредственно в HTML. Они читаются через /api/app-info из site_links и admin_contacts. В панели администратора появился раздел «Контакты»: там можно редактировать ссылки и контакты, добавлять новые, менять видимость и выбирать основной контакт для кнопки обратной связи. Изменения сразу сохраняются в SQLite.

МИГРАЦИИ И РЕЗЕРВНАЯ КОПИЯ
При старте сервер безопасно добавляет недостающие колонки и таблицы через CREATE TABLE IF NOT EXISTS / ALTER TABLE, не удаляя существующие клубы. Перед заменой hse_nn_clubs.db или обновлением базы всегда делайте резервную копию. Если подменяете файл базы новой выгрузкой, проверьте наличие таблиц users, subscriptions, requests, request_files, request_status_history, app_notifications, user_activity, broadcasts, broadcast_recipients, admin_accounts, admin_access_attempts, admin_audit_log, site_links, admin_contacts и app_settings; миграции создадут отсутствующие таблицы, но данные из старого файла автоматически не переносятся.
